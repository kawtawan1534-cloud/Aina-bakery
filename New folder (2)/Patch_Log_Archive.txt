Patch 4.4.0: แก้บั๊กหักเงินสดซ้ำซ้อนใน outputSales() (Patch Numbering Y)
  - อาการ: cashEnd = cashStart - productionCostToday + revenueToday -
    reorderCostToday หักเงินสดวัตถุดิบ 2 รอบสำหรับของชุดเดียวกัน —
    reorderCostToday คือเงินสดจริงที่จ่ายตอนซื้อวัตถุดิบมาเติมสต็อก ส่วน
    productionCostToday คือมูลค่าวัตถุดิบที่ "ใช้ไป" ตอนผลิต ซึ่งจ่ายเงินไป
    แล้วตั้งแต่ตอน reorder (หรือตอนซื้อสต็อกเริ่มต้นวันเปิดร้าน) ไม่ใช่เงินสด
    ใหม่ที่ต้องจ่ายอีก
  - พบระหว่างวิเคราะห์ย้อนหลัง Day 1-16 (จำลอง): รายรับรวม 5,717 บาท,
    ต้นทุนผลิตรวม 5,130 บาท, reorder รวม 4,383 บาท → ขาดทุนสุทธิ 3,796 บาท
    ทั้งที่กำไรจากของที่ขายได้จริง (มาร์จิ้น ~40%) เป็นบวก 2,264 บาท —
    ถ้าคิดสูตรใหม่ (ไม่หัก productionCost) กำไรสุทธิ 16 วันจะเป็น +1,334
    บาทแทนที่จะขาดทุน -3,796 บาท
  - แก้โดยเอา productionCostToday ออกจากสูตรคำนวณ cashEnd แต่ยัง return
    ค่าไว้เป็นตัวเลขรายงาน (COGS/margin ต่อวัน) — สูตรใหม่:
    cashEnd = cashStart + revenueToday - reorderCostToday
  - หมวด Y (ไม่ใช่ Z) เพราะเปลี่ยนโครงสร้างสูตร outputSales() ทั้งเทอม
    ไม่ใช่แค่ปรับ coefficient/threshold เดียวแบบ Patch 4.3.2
  - Layer ที่กระทบ: OUTPUT (ยอดขาย) → กระทบเงินสดคงเหลือทุกวันย้อนหลัง
    ตั้งแต่มี Reorder Logic Layer (Patch 4)
