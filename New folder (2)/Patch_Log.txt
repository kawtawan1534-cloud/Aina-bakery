  === ส่วนที่ 2 (ต่อเนื่องกัน วันเดียวกัน — ยังนับเป็น Patch 5.0.0) ===
  ตัดข้อมูลดิบ (recipe/costRates/prices/stockMax/reorderThreshold) ออกจาก
  Engine Noname.ps1 ไปอ่านจากไฟล์ JSON แทน (Excel-style reference + error)
  - เหตุผล: แม้ Engine Noname.ps1 จะเป็น engine หลักแล้ว แต่ยังฝังค่าคงที่
    ซ้ำกับไฟล์ .txt อ้างอิงเดิมอยู่ (Production Recipe per Piece.txt.txt,
    Production.txt, Stock เริ่มต้น.txt) เสี่ยงหลุด sync แบบเดียวกับที่เพิ่งแก้
    ไปตอน promote — ผู้เล่นเสนอให้ engine มีแค่ "สูตร/logic" + "คำสั่งอ้างอิง
    ไฟล์ข้อมูล" เทียบเท่าสูตร Excel ที่ error ทันทีถ้าอ้างอิงพัง (`#REF!`)
    แทนที่จะคำนวณต่อแบบเงียบๆ ด้วยค่าที่อาจผิด
  - ตัดสินใจ: แปลงไฟล์อ้างอิงเป็น JSON (ไม่ใช่เขียน parser อ่าน syntax เดิม)
    เพราะ parser เองก็เป็นจุดเสี่ยง parse ผิดแบบเงียบๆ ได้เหมือนกัน ขัดกับ
    เป้าหมายหลัก (error ชัดเจน ไม่ใช่ผลลัพธ์ผิดแบบไม่รู้ตัว) — คอมเมนต์ "ทำไม"
    ที่เคยอยู่ในไฟล์ .txt (เช่นประวัติ redbean 0.5→2.0) ไม่ได้หายไปไหน เพราะซ้ำ
    กับที่มีอยู่แล้วเต็มๆ ใน Patch_Log.txt นี้อยู่แล้ว
  - ไฟล์ใหม่ 3 ไฟล์ (แหล่งข้อมูลจริงที่ engine อ่าน):
      - Production Recipe per Piece.json → recipe, costRates
      - Production.json → menu (price + locked ต่อเมนู)
      - Stock เริ่มต้น.json → stockMax, reorderThreshold, initialCash
  - ไฟล์ .txt เดิม 3 ไฟล์ (Production Recipe per Piece.txt.txt, Production.txt,
    Stock เริ่มต้น.txt) เหลือไว้เป็นเอกสารอ่านอ้างอิงสำหรับคนเท่านั้น เพิ่ม
    หัวไฟล์เตือนชัดว่าแก้แล้วไม่มีผลกับเกมจริง ต้องแก้ที่ .json คู่กัน
  - Engine Noname.ps1: เพิ่ม `Read-DataFile()` (throw error ถ้าไม่พบไฟล์/
    ไฟล์ว่าง) + `ConvertTo-Hashtable()` (แปลง PSCustomObject จาก
    ConvertFrom-Json ให้เป็น Hashtable ใช้ index แบบเดิมได้ไม่ต้องแก้โค้ด
    ส่วนอื่น) + loop เช็คความครบถ้วนข้ามไฟล์หลังโหลด (ทุกเมนูที่ปลดล็อกต้องมี
    recipe, ทุกวัตถุดิบในสูตรต้องมี costRates/stockMax/reorderThreshold —
    ขาดตัวไหน throw ระบุชัดว่าขาดอะไร ใช้ที่ไหน)
  - บั๊กที่เจอระหว่างทำ (แก้แล้ว): Engine Noname.ps1 ไม่มี UTF-8 BOM ทำให้
    Windows PowerShell 5.1 อ่านคอมเมนต์/ข้อความไทยผิด codepage พอเพิ่ม throw
    string ภาษาไทยใหม่เข้าไปเลย parse error ทั้งไฟล์ (คอมเมนต์เก่าที่เคยรัน
    ผ่านมาตลอดก็พังไปด้วยเป็น side effect) — แก้โดย resave ไฟล์เป็น UTF-8
    with BOM ครั้งเดียว แก้ปัญหาถาวร ไม่ใช่แค่รอบนี้
  - ทดสอบก่อนสรุป: (1) รันแบบ no-op เทียบค่าที่โหลดได้ (recipe.melonpan.butter,
    costRates.egg, prices.Count ฯลฯ) กับค่าดั้งเดิมทุกตัวตรงกัน (2) ลบ/
    rename Production.json ชั่วคราวแล้วรัน → ได้ error ข้อความไทยชัดเจนบอก
    ไฟล์ไหนหาย ใช้เพื่ออะไร ตรงเป้าหมาย Excel #REF! (3) rename ไฟล์กลับ รัน
    ซ้ำผ่านปกติ ไม่กระทบ state จริง
  - Layer ที่กระทบ: MEMORY LAYER เท่านั้น (ที่มาของ recipe/costRates/prices/
    stockMax/reorderThreshold) ไม่กระทบสูตรคำนวณ/ผลลัพธ์ pipeline เลย
    (ตัวเลขที่โหลดได้เหมือนเดิมทุกตัว แค่เปลี่ยนที่มา)

Patch 5.0.1: ปัด 6 ตำแหน่งกัน floating point คลาดเคลื่อนสะสมในสต็อก (Patch
Numbering Z — แก้บัค ไม่เปลี่ยนโครงสร้าง)
  - อาการ: Day 52 (จำลอง) Butter มี 330g ต้องใช้ 330g พอดี (ควรผลิตได้ 100%
    เป๊ะ) แต่ minRatio ออกมา 0.99999999999999944 แทนที่จะเป็น 1.0 พอดี ทำให้
    Math.Floor() ปัดยอดผลิตลง 1 ชิ้นทุกเมนู (5/8/3 → 4/7/2) ทั้งที่วัตถุดิบไม่ได้
    ขาดจริง
  - สาเหตุ: `$stock[$mat] -= ($usedG / 1000)` ลบทศนิยม (เช่น 105/1000=0.105)
    ที่แทนค่าแบบเป๊ะในเลขฐาน 2 ไม่ได้ ทำซ้ำมา 52 วันจนคลาดเคลื่อนสะสมถึงระดับ
    10⁻¹³ — ปกติจมหายไปในตัวเลขหลักร้อย ไม่มีผล แต่พอสต็อกบังเอิญตรงเป๊ะกับที่
    ต้องใช้ (ratio ควรเป็น 1.0 พอดี) ความคลาดเคลื่อนจิ๋วนี้ดันค่าต่ำกว่า 1 นิดเดียว
    แล้วโดน floor() ปัดลงจริง
  - แก้: ปัด `[Math]::Round(..., 6)` ทุกครั้งหลังลบสต็อก — วัตถุดิบจริงคำนวณเป็น
    กรัมเต็มเสมอ (ละเอียดสุด 3 ตำแหน่งทศนิยมของหน่วย kg) ปัด 6 ตำแหน่งจึงตัด
    เฉพาะ noise ระดับ 10⁻¹³ ทิ้ง ไม่กระทบความละเอียดจริงเลย
  - เก็บกวาดข้อมูลเก่า: sim_state.json ตอนนั้นมีค่าสต็อกคลาดเคลื่อนสะสมอยู่แล้ว
    หลายตัว (yeast, flour, redbean, milk — เห็นชัดจากทศนิยมยาวๆ ที่ไม่ควรมี)
    ปัด 6 ตำแหน่งให้สะอาดครั้งเดียวพร้อมกับแก้โค้ด (butter สะอาดอยู่แล้วเพราะเพิ่ง
    reorder วันเดียวกัน ซึ่ง set ค่าตรงๆ ไม่ผ่านการลบสะสม)
  - ทดสอบ: รันแบบ no-op หลังแก้ (state อยู่ Day 52 อยู่แล้ว) ผ่านปกติ ไม่มี error
  - Layer ที่กระทบ: CORE (StockCheck ใช้ค่าที่ปัดแล้ว) — กระทบเฉพาะกรณีสต็อก
